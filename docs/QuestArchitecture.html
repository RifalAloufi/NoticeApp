Notice – Quest Logic Architecture

How today's 3 quests are chosen, shown, and completed. Everything runs on the phone, with no internet needed.

2. How today's 3 quests are picked (QuestProvider)

3. What each part does

PartFileResponsibility
Quest listMyApp/Quests.jsonThe 45 quests, bundled in the app. Edit this file to change the quests (keep the count a multiple of 3).
QuestProviderModels/QuestProvider.swiftLoads the list once and returns the 3 quests for any date. Falls back to 3 built-in quests if the file is missing.
HomeContainerViews/Home/HomeContainer.swiftReads today's quests and the saved photos, counts the photos taken today, and reloads when the app returns or the camera closes.
HomeViewViews/Home/HomeView.swiftShows the current quest (quests[done today]), the progress, the diary, and opens the camera.
PhotoStorageViews/Camera/PhotoStorage.swiftSaves each photo with its quest name and date. This is the only progress record, so there is no separate "quest progress" file.
Capture flowViews/Camera/…Permission check, camera, review and save.

4. Rules to keep in mind

  • Offline by design: nothing uses the network. The date picks the quests and the saved photos are the progress.
  • New day, new quests: when the app comes back to the foreground on a new day, the 3 quests change and progress goes back to 0/3. Yesterday's photos stay in the diary.
  • Never change the start date (1 Jan 2026) or the shuffle, or everyone's quests shift.
  • Known gaps: a 4th capture isn't blocked, and "done today" counts any photo taken today without checking its quest name. The phone's clock decides the day, so changing the date skips quests.
